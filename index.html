How to use Traffic App

Counting modes

Traffic App has two counting modes. Choose based on what data you're collecting:

Directional vehicle count
Counts vehicles entering and leaving an area — each vehicle type has an IN key and an OUT key. Use this for approach volumes, cordon counts, or any study where direction matters. Set up under vehicle types in intersection setup.
Turning movement count (TMC)
Records which direction each vehicle turns at an intersection — each type has one key, and you click the cell in the turning grid for the movement you observed. Use this for signal timing, capacity analysis, or any study requiring turn-by-turn volumes. Set up under turning movement in intersection setup.

Importing count data

Use Import XLSX on the home screen or inside an area study to load standard TMC or pedestrian count spreadsheets. The app auto-detects the format — if the file contains "Turning movement" in the header rows it's parsed as a TMC; otherwise it tries the pedestrian count format.

After import the app opens the intersection directly so you can review data, run analysis, and export.

Data privacy and multi-user safety

Each device that opens Traffic App has its own completely isolated storage. Sharing the URL does not share data — another user opening the same link sees a blank app with their own empty storage.

Cross-contaminationNot possible. Two field workers on different devices are completely independent. Worker A's data cannot overwrite or be seen by Worker B.
Same device, two usersProjects are identified by name and UUID. If two people share the same device and browser, they share the same storage. Use clear project names to tell them apart, and export each project to a file when done.
Sensitive dataTraffic App stores count data, street names, and project metadata — no personal information or credentials. Data lives only in the local browser storage on your device.
Moving dataThe only way data crosses devices is via an explicit sync export (.tcsync file) that you create and share yourself. There is no automatic or background sync.

Saving and syncing

Projects auto-save to this browser. To move data to another device, use Cross-device sync on the home screen — export all projects to a .tcsync file, then import it on the other device. Projects are merged by ID; existing ones are not overwritten.

To share or back up a single project, use Export ? Project package (.zip) from the workspace export tab.

how to use

overview

A keyboard-driven field counter for traffic studies. Configure your intersection once in setup, then count by keystroke against time-lapse video. Three independent modes share the same session: vehicle (in/out by type), pedestrian (crossings by crosswalk and direction), and TMC (turning movement counts by approach leg).

This help covers single-intersection counting. Traffic App also supports Area-wide studies (multiple intersections reviewed and exported together) and Trip Generation counts (per-location classification counts with a Distribution tab for allocating generated trips to nearby intersections) — both are started from the home screen and use the same counting mechanics described here.

basic workflow

  • Fill in the setup tabs — study parameters, intersection layout (crosswalks and approaches), counting types, and filenames.
  • Click start counting to enter the counter.
  • Run your video. Use the video clock to track interval boundaries.
  • Press ↓ each time the clock crosses an interval boundary.
  • Count with the keyboard shortcuts shown in the reference bar. Switch between vehicle, pedestrian, and TMC modes with the toggle in the header — each keeps independent data.
  • Click .csv or .xlsx in the header to export at any time.

navigation, editing & correction

↓advance to next interval ↑go back to previous interval Zundo last action Yredo

Edit a cell: click any count cell, type the corrected value, press Enter or Esc. Edited cells are highlighted.

Reset an interval: right-click any time label to reset it. Single undoable action.

focus mode

Lock input to one target at a time — useful when traffic is heavy and you want to watch the video once per movement or crosswalk.

QA/QC recounts

Every project type has a QA/QC screen, reachable from the sidebar, for having a second counter re-count one peak hour and compare it against the original — useful for catching miscounts or inter-counter variance. Recounts show raw counts and differences alongside a pass/fail score, not just a badge.

important

  • Counts live in this browser tab only — do not close or refresh during a session.
  • Window focus is required. If you click into a video player, keystrokes go there. A red banner appears when focus is lost — click anywhere on the counter to resume.
  • Export before ending any session.

study parameters

  • Start time — clock time of the first interval (e.g. 06:00). All row labels and CSV exports use real clock times.
  • Interval length — duration of each counting period. Choose a preset or enter a custom value in minutes.
  • Duration — total study length. Row count is calculated automatically as duration ÷ interval.

intersection builder

Choose a template (T / 4-way / 5-way), enter street names, then configure each leg independently. Each leg panel has two toggles:

  • Crosswalk — enables pedestrian counting on that leg. Set the crosswalk name, both direction labels, and key bindings.
  • Approach — enables turning movement counting from that leg. Check the destination legs you want to record.

Street names flow into destination labels (e.g. Thru (N) — Seminole Ave) and into default export filenames. The live diagram on the right shows crosswalk zones and approach arrows simultaneously as you build.

counting types

One master list drives both vehicle and TMC counting — there's no separate vehicle-types vs. TMC-types setup anymore. Each row is a type with a label, an IN key, and an OUT key for vehicle (in/out) counting. Check a row's TMC box to also include it in turning movement counts, assigned its own TMC key. Drag a row's handle to reorder; rows lock once count data exists for that type, so fix labels and key conflicts before you start counting. Two FHWA presets are available, and a + bicycle button adds a locked "Bicycle" row for consistent bike data across studies.

export filenames

Filenames default to Street1_Street2_TypeOfCount once street names are entered. All three can be changed mid-session via the settings button.

what it's for

The numpad one-handed layout puts every type's IN and OUT key on the number pad, in pairs, so you can count with one hand while the other holds a clicker, scrubs video, or does something else entirely. It's the default for Trip Gen counting; the intersection counter offers it as an option under "counting types."

More than 4 types split into groups the same way QWERTY does — switch groups with Numpad / / Numpad -, or the ‹ › buttons next to the keyboard reference.

in focus mode

While focus mode is on, Numpad 7 and Numpad 9 always record IN / OUT for whichever type is currently focused — regardless of that type's own assigned keys, and even on the QWERTY preset. One fixed pair to reach for, no matter what's focused.

density options

Alongside the QWERTY/Numpad preset, a density picker controls how many types share each keybinding group: standard (4 types per group, in + out each), one-handed pairs (2 types per group, in + out each — fits entirely under one hand), or all-in/all-out (up to 4 types per group, one key each, single direction only).

changing the preset

Both the intersection counter's "counting types" tab and Trip Gen's "classifications" tab have a key preset row — QWERTY or Numpad one-handed — plus the density options described in the number pad tab. Click a preset button to switch.

what switching actually does

Only new rows pick up the new preset's keys — switching presets never rewrites keys already assigned to existing types or classifications, so it's safe to change mid-project without scrambling data you've already recorded under the old keys.

editing one row's key directly

Every row has its own IN/OUT key input — type into it to override the preset's default for just that row. A key already in use elsewhere in the same group is flagged in red; fix the conflict before counting, since two rows sharing a key means only one of them can ever register.

groups

More than 4 types (or 2, under the one-handed-pairs density) split into groups that reuse the same physical keys — switch the active group with the dedicated group-switch keys, or the ‹ › buttons next to the keyboard reference. See the vehicle tab for the exact default group-1 keys.

key layout

Each vehicle type has an IN key (left hand) and an OUT key (right hand). Up to 4 types are shown at once; if you have more, they're split into groups — press [ or ] to cycle groups, or click the group buttons in the config bar.

mid-session changes

Vehicle type labels can be edited from the config bar below the header without losing data. Key assignments can be changed mid-session via the settings button — no restart required.

output

Two side-by-side tables show inbound and outbound counts. The CSV has separate INBOUND and OUTBOUND sections, one row per interval, one column per type, with totals.

structure

Counts crossing events by crosswalk and direction. Each crosswalk has two direction keys. All crosswalks share one unified table with a colored column pair per crosswalk.

intersection diagram

Open with the diagram button in the header. The floating diagram window shows your intersection with colored crosswalk bands, direction keys, and live counts for the current interval. Each keystroke briefly animates the matching count — peripheral confirmation without looking away from the video. Focus mode highlights the active crosswalk and dims the rest.

mid-session changes

Crosswalk names and direction labels can be edited from the config bar while counting. Key assignments can be changed via the settings button. Template, slot assignments, and crosswalk count are fixed once counting begins.

output

CSV mirrors the on-screen table — time column, two direction columns per crosswalk, per-column and grand totals.

what is TMC mode?

Turning Movement Count mode records vehicles by approach leg and destination movement (left, through, right, U-turn). Configure approach legs in the intersection builder on the setup screen.

workflow

  • Switch to TMC in the mode toggle.
  • Select the active approach leg from the movement bar below the header, or use [ / ] to cycle between legs.
  • The keyboard reference shows one key per destination movement. Press a key to count a vehicle making that turn.
  • Vehicle type keys (IN keys from your vehicle setup) select which type is being counted for that movement.

turning diagram

The compact SVG diagram in the header shows all movements for the current approach with live counts. Open the full turning diagram popup for a larger view with a counts table by vehicle type and movement — useful on a second monitor positioned over the video.

destination labels

Destinations are labeled by movement and street name — e.g. Thru (N) — Seminole Ave, Left (W) — Morris Park Ave. Labels update live when you edit street names in setup.

output

TMC CSV exports one section per approach leg, with rows for each interval and columns for each destination × vehicle type combination.

exporting

Click the .csv or .xlsx button in the header to download the current mode's data. Vehicle and pedestrian modes export separately, using the filenames set in setup (editable mid-session via the settings button). From the workspace Export screen you can also download a shareable HTML report page or a full project package (.zip) with everything bundled together.

Excel compatibility

Files include a UTF-8 byte-order mark so special characters like the en-dash in time ranges (e.g. 06:00–06:15) display correctly in Excel without any manual import steps.

mid-session settings

The settings button opens a small dialog for changing export filenames without interrupting your session. Structural changes — interval length, duration, type or crosswalk counts — require returning to setup, which warns before clearing counts.

data safety

  • All counts are held in memory in this tab. Closing or refreshing loses them.
  • Export regularly, and always before resetting or returning to setup.
  • For multi-session work, export and rename each CSV before starting the next.

moving projects between devices

Each device has its own separate, isolated storage — nothing syncs automatically. Use Cross-device sync on the home screen to export every saved project into one .tcsync file, then import that file on another device. Projects are merged by ID, so importing never overwrites an existing project with the same one.

reporting a problem

Use Report a bug in the sidebar (or on the home screen) to describe what happened. You can send it by email or download a JSON file with your description and app state attached — nothing is sent automatically, and no count data leaves your device unless you choose to attach it yourself.

settings

Label and filename changes apply immediately. To change interval length, duration, or pair counts return to setup — structural changes reset count data.
